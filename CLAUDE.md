# Трекер цикла (аналог Flo) — правила проекта

Полный план продукта: `docs/plan.md` (исходник — `docs/plan.pdf`). Этот файл — краткие правила для ИИ-помощника.

@AGENTS.md

## Продукт в двух словах

- Трекер цикла: сначала сайт → PWA → мобильное приложение (Capacitor или Expo).
- Ядро — **режим пары**: партнёр видит только то, что владелица включила переключателями.
- Интерфейс **только на русском**. Хостинг **только в ЕС** (Supabase и Vercel, Франкфурт).
- Базовые функции работают без регистрации (гостевой режим, IndexedDB); регистрация — вход по коду на почту.
- Монетизация — премиум-подписка, но не в MVP.

## Стек

Next.js (App Router) + TypeScript + Tailwind · Supabase (Postgres, Auth, Realtime) · Vitest · Serwist (PWA, позже) · Resend · Plausible.

## Структура

```
src/app/                 страницы (App Router)
src/components/          экраны: онбординг, вкладки «Сегодня» / «Календарь» / «Настройки», журнал дня
src/lib/cycle/           прогноз, отметки месячных, разметка календаря — чистые функции, без React и без базы
src/lib/guest/           гостевой режим: хранение в IndexedDB
src/lib/journal.ts       журнал дня: список симптомов и настроений
src/lib/sync/            синхронизация с аккаунтом: что отправить (diff), перенос гостевых данных, запросы к Supabase
src/lib/supabase/        клиенты Supabase (браузер / сервер)
supabase/migrations/     схема базы и правила доступа (RLS) — единственный источник правды
supabase/tests/          проверки правил доступа
scripts/test-db.sh       прогон миграций и проверок на временном локальном Postgres
docs/                    план продукта
```

## Команды

- `npm run dev` — локальный сервер
- `npm test` — юнит-тесты (Vitest)
- `npm run typecheck`, `npm run lint`, `npm run build`
- `scripts/test-db.sh` — проверки доступа к базе (нужен локальный Postgres 15+)

Перед каждым коммитом: `npm test && npm run typecheck && npm run lint`, а при изменении `supabase/` — ещё `scripts/test-db.sh`.

## Никогда

- **Не давать партнёру прямой доступ к таблицам владелицы.** Всё, что видит партнёр, идёт только через `public.get_partner_view()`, которая учитывает `share_settings` и пишет в `access_log`. Личные заметки, температура и тесты на овуляцию партнёру не уходят никогда.
- Не ослаблять RLS ради удобства интерфейса. Новая таблица → сразу `enable row level security` + политики + тест в `supabase/tests/rls_test.sql`.
- Не хранить коды приглашения в открытом виде — только хэш; код одноразовый, живёт 24 часа.
- Не подключать рекламные SDK и сторонние трекеры (Google Analytics, Facebook Pixel и т. п.). Аналитика — только Plausible.
- Не получать доступ к рабочей базе с реальными данными и не класть её ключи в репозиторий. Только тестовый проект Supabase, ключи — в `.env.local`.
- Не писать в интерфейсе диагнозов и не называть прогноз методом контрацепции. Предупреждения — мягкие, с советом обратиться к врачу.
- Не использовать `Date.now()`/`new Date()` внутри `src/lib/cycle` — «сегодня» передаётся параметром.
- Не держать даты цикла как `Date` с часовым поясом: только строки `YYYY-MM-DD` (см. `src/lib/cycle/dates.ts`).

## Как работать

- Одна задача — одна функция, коммит после каждой работающей функции.
- Порядок: схема и правила доступа → прогноз с тестами → экраны → режим пары.
- После крупной правки — коротко объяснить, что изменено и что может сломаться.
- Тексты интерфейса — на русском. В коде и документах: пользовательница — «владелица», второй участник — «партнёр».
